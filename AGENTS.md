# Muesli: notes for coding agents

Muesli is an on-device meeting transcriber for **macOS and Windows**. It records the microphone ("You") and system audio ("Others"), transcribes with Whisper locally, writes Markdown and JSON transcripts, and exposes them to AI assistants through an MCP server (`muesli-mcp`, stdio).

## Two apps, one contract
- **macOS ships the Swift app**: `macos/` (`Sources/Muesli` app, `Sources/MuesliCore` Foundation-only logic). Its `muesli-mcp` is the Rust binary from `windows/crates/mcp`, built by `macos/build.sh` (needs a Rust toolchain). Build with `macos/build.sh`, test with `cd macos && swift test`.
- **Windows ships the Rust and Tauri app**: `windows/` (crates `core`, `mcp`, `whisper`, `audio`, `detect`, `system`, plus `src-tauri` and `ui/`). Test with `cd windows && cargo test --workspace`, lint with `cargo clippy --workspace --all-targets -- -D warnings`. It also builds and runs on macOS, which is how it is developed and tested from a Mac; that is a development convenience, not a second macOS product.
- **Both apps are permanent.** Neither replaces the other. A feature is done when it works in both, or when `docs/PLATFORMS.md` records why one platform differs.
- Both read and write the same files (`config.json`, `state.json`, `meetings/*.json`, transcripts) and offer the same seven MCP tools. **The shared logic lives once, in the Rust crates.** The macOS app reaches it through UniFFI (`windows/crates/ffi`, built by `scripts/build-ffi.sh` into a git-ignored XCFramework and generated Swift). Already shared: meetings, paths, preferences, `state.json`, the transcript and meeting stores, languages, the model downloader, Whisper transcription with voice activity detection and MCP client snippets, plus the `muesli-mcp` binary. Also shared now: detection rules, audio chunking, the Claude Desktop config and extension code, and audio files (decoding in `crates/audio`, `crates/import`, the drop folder in core). What is left in Swift is OS glue and tiny helpers (`Languages.displayName`, `RecentTranscript.subtitle`, `WhisperModel.unused`). Logic goes in the Rust crates, with a wrapper in `windows/crates/ffi`; never in `MuesliCore`. `fixtures/` at the repo root freezes the file formats (`fixtures/core`) and the MCP replies (`fixtures/mcp`), checked by `windows/crates/core/tests/golden.rs` and `windows/crates/mcp/tests/contract.rs`; edit those files by hand, on purpose, when a format or reply changes.

## Rules
- Logic goes in the core (`macos/Sources/MuesliCore` / `windows/crates/core`) with tests. The app targets (`macos/Sources/Muesli`, `windows/src-tauri`) stay thin: UI, OS calls, wiring.
- Use libraries for the hard parts (resampling: `rubato`; audio devices: `cpal`; atomic writes: `tempfile`; ids: `uuid`). Do not hand-roll replacements.
- Audio is never written to disk. The only network request is the Whisper model download.
- Transcribing must be impossible while no model is ready, and nothing may prompt for a permission outside its onboarding screen.
- Platform differences are documented in `docs/PLATFORMS.md`, split into what the platform imposes (for example: Windows has no system calendar and needs no system-audio permission) and what is simply not done yet. Before calling something impossible on a platform, check it and record the reason there.
- Follow `assets/brand/BRAND.md` for logo, colours and tone. `assets/brand` is the only source for icons: `windows/src-tauri/icons/` is generated by `scripts/sync-icons.py`, never edited.
- Nothing platform-specific lives at the repo root. Shared things go in `assets/`, `fixtures/`, `scripts/` or `docs/`.
- `plugin/` is a Claude plugin (installed from this repo; its `server/muesli-mcp.js` launcher starts `muesli-mcp` on both platforms, and both apps write `mcp-path` for it); keep it in step with `muesli-mcp` (tool list in its skill and README) and run `python3 scripts/sync-plugin.py` after a version bump. `plugin/LICENSE`, `plugin/icon.png` and the plugin version are generated by that script.
- Keep `README.md` (users), `CONTRIBUTING.md` (developers), `docs/REQUIREMENTS.md`, `docs/PLATFORMS.md` and this file current with every change.

## Verifying
- Swift: `cd macos && swift test`, then `macos/build.sh` and run `macos/Muesli.app`.
- Rust: `cd windows && cargo test --workspace`; from a Mac, `cargo check --target x86_64-pc-windows-msvc -p muesli-core -p muesli-mcp -p muesli-audio -p muesli-detect -p muesli-system` type-checks most Windows code. `src-tauri` and `whisper` only compile for Windows in CI (`.github/workflows/ci.yml`); installers come from `app.yml`. Both workflows are started by hand, so nothing checks a push automatically: run the tests locally before pushing.
- Say plainly what was not run on Windows. `docs/PLATFORMS.md` section 3 records what has been verified there (so far: a recording, tested by the maintainer).
