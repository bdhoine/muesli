# Muesli: notes for coding agents

Muesli is an on-device meeting transcriber for **macOS and Windows**. It records the microphone ("You") and system audio ("Others"), transcribes with Whisper locally, writes Markdown and JSON transcripts, and exposes them to AI assistants through an MCP server (`muesli-mcp`, stdio).

## Two apps, one contract
- **macOS ships the Swift app**: `macos/` (`Sources/Muesli` app, `Sources/MuesliCore` Foundation-only logic). Its `muesli-mcp` is the Rust binary from `crates/mcp`, built by `macos/build.sh` (needs a Rust toolchain). Build with `macos/build.sh`, test with `cd macos && swift test`.
- **Windows ships the Rust and Tauri app**: `crates/` (`core`, `mcp`, `whisper`, `audio`, `import`, the adapters `platform-common`, `platform-windows`, `platform-macos`, `platform-fake`, and `port-contracts`), the Tauri shell in `apps/desktop` and the web UI in `ui/`, all in one Cargo workspace at the repo root. Test with `cargo test --workspace`, lint with `cargo clippy --workspace --all-targets -- -D warnings`. It also builds and runs on macOS, which is how it is developed and tested from a Mac; that is a development convenience, not a second macOS product.
- **Both apps are permanent.** Neither replaces the other. A feature is done when it works in both, or when `docs/PLATFORMS.md` records why one platform differs.
- Both read and write the same files (`config.json`, `state.json`, `meetings/*.json`, transcripts) and offer the same seven MCP tools. **The shared logic lives once, in the Rust crates.** The macOS app reaches it through UniFFI (`crates/ffi`, built by `scripts/build-ffi.sh` into a git-ignored XCFramework and generated Swift). Already shared: meetings, paths, preferences, `state.json`, the transcript and meeting stores, languages, the model downloader, Whisper transcription with voice activity detection and MCP client snippets, plus the `muesli-mcp` binary. Also shared now: detection rules, audio chunking, the Claude Desktop config and extension code, and audio files (decoding in `crates/audio`, `crates/import`, the drop folder in core). What is left in Swift is OS glue and tiny helpers (`Languages.displayName`, `RecentTranscript.subtitle`, `WhisperModel.unused`). Logic goes in the Rust crates, with a wrapper in `crates/ffi`; never in `MuesliCore`. `fixtures/` at the repo root freezes the file formats (`fixtures/core`) and the MCP replies (`fixtures/mcp`), checked by `crates/core/tests/golden.rs` and `crates/mcp/tests/contract.rs`; edit those files by hand, on purpose, when a format or reply changes.

## Rules
- **Ports and adapters.** The core never calls the OS. Every OS service is a trait in `crates/core/src/ports.rs`; `platform-macos` and `platform-windows` implement them, `platform-fake` fakes them for tests and the simulator, and `port-contracts` holds one suite per port that every adapter must pass. A new OS call means a port method, a fake, a contract and the native adapters.
- Logic goes in the core (`macos/Sources/MuesliCore` / `crates/core`) with tests. The app targets (`macos/Sources/Muesli`, `apps/desktop`) stay thin: UI, OS calls, wiring.
- Use libraries for the hard parts (resampling: `rubato`; audio devices: `cpal`; atomic writes: `tempfile`; ids: `uuid`). Do not hand-roll replacements.
- Audio is never written to disk. The only network request is the Whisper model download.
- Transcribing must be impossible while no model is ready, and nothing may prompt for a permission outside its onboarding screen.
- Platform differences are documented in `docs/PLATFORMS.md`, split into what the platform imposes (for example: Windows has no system calendar and needs no system-audio permission) and what is simply not done yet. Before calling something impossible on a platform, check it and record the reason there.
- Follow `assets/brand/BRAND.md` for logo, colours and tone. `assets/brand` is the only source for icons: `apps/desktop/icons/` is generated by `scripts/sync-icons.py`, never edited.
- Nothing platform-specific lives at the repo root. Shared things go in `assets/`, `fixtures/`, `scripts/` or `docs/`.
- `plugin/` is a Claude plugin (installed from this repo; its `server/muesli-mcp.js` launcher starts `muesli-mcp` on both platforms, and both apps write `mcp-path` for it); keep it in step with `muesli-mcp` (tool list in its skill and README) and run `python3 scripts/sync-plugin.py` after a version bump. `plugin/LICENSE`, `plugin/icon.png` and the plugin version are generated by that script.
- Keep `CHANGELOG.md` current: every change a user can see or use gets a line under `[Unreleased]` (Added, Changed, Fixed, Removed), in plain end-user words; no refactors or internals. When the version is bumped, rename `[Unreleased]` to the new version with its date and update the compare links at the bottom.
- Keep `README.md` (users), `CONTRIBUTING.md` (developers), `docs/REQUIREMENTS.md`, `docs/PLATFORMS.md` and this file current with every change.

## Verifying
- Swift: `cd macos && swift test`, then `macos/build.sh` and run `macos/Muesli.app`.
- Rust: `cargo test --workspace` (at the repo root); from a Mac, `cargo check --target x86_64-pc-windows-msvc -p muesli-core -p muesli-mcp -p muesli-audio -p muesli-platform-windows` type-checks most Windows code. `apps/desktop` and `whisper` are fully checked for Windows only in CI (`.github/workflows/ci.yml`); installers come from `app.yml` (workflows **Tests** and **Build installers**, which also run on macOS). Both workflows are started by hand, so nothing checks a push automatically: run the tests locally before pushing.
- Say plainly what was not run on Windows. `docs/PLATFORMS.md` section 3 records what has been verified there (so far: a recording, tested by the maintainer).
